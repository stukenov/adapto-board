# Decisions (ADR-lite)

## D001 — Kotlin-only по всему стеку

- Решение: backend + admin UI + Android TV app делаем на Kotlin.
- Причина: скорость команды, единая модель данных, меньше контекстов.
- Компромисс: web UI варианты менее зрелые, чем JS-экосистема.

## D002 — Android TV как единственная платформа v1

- Решение: поддерживаем только Android TV.
- Причина: минимизация QA матрицы и операционной поддержки.
- Компромисс: часть клиентов с Tizen/webOS откладываем на R2+.

## D003 — Один монолит вместо микросервисов

- Решение: один Ktor монолит с внутренними модулями.
- Причина: меньше систем, проще деплой/наблюдаемость, быстрее пилот.
- Компромисс: нужна дисциплина модульных границ и миграционный план на рост.

## D004 — SSE для overlay

- Решение: realtime слой делаем через SSE.
- Причина: проходит через прокси проще, чем WS; реализация проще.
- Компромисс: соединения долгоживущие, нужно следить за ресурсами.

## D005 — Postgres как “центр правды”

- Решение: Postgres — единственная обязательная внешняя система в v1.
- Причина: транзакции, индексы, ретеншн, простота эксплуатации.
- Компромисс: аккуратно проектировать as-run объёмы и ретеншн.

## D006 — Admin UI только web

- Решение: админка — только web UI.
- Причина: проще внедрение в enterprise (доступ по URL), быстрее rollout и поддержка.
- Компромисс: web-ограничения/кроссбраузерность; “Kotlin-only” достигаем через Compose Multiplatform for Web.
