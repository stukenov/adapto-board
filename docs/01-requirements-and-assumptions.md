# 01 — Требования, ограничения и допущения

## 1) Контекст

PRD в `about.txt` описывает Playout Edge как платформу corporate TV / digital signage с multi-tenant, управлением каналами/расписанием, парком устройств, realtime overlays (data layer), audit + as-run.

Уточнения (фиксируем как “жёсткие ограничения v1”):

- Весь стек — **Kotlin**: backend + admin UI + Android TV приложения.
- Поддерживаемые конечные устройства — **только Android TV** (v1).
- Архитектура backend — **не “зоопарк микросервисов”**, а **один full-stack Kotlin** (монолит) с минимальным количеством внешних систем.
- Фокус — “делаем максимально меньше, но самое важное” (MVP продаётся и работает 24/7).

## 2) Главные бизнес-цели (must win)

1. Пилот 50–200 экранов за 2–4 недели без героизма.
2. Production 1k–10k экранов при понятной эксплуатации.
3. Публикация изменений “минуты, не дни”.
4. Данные и безопасность “как у enterprise”: RBAC/SSO (поэтапно), аудит, предсказуемые релизы.

## 3) Product scope v1 (минимум, который продаётся)

### 3.1 Must-have (v1)

- Multi-tenant (жёсткая изоляция данных).
- Каналы и простое расписание (draft → publish, версия).
- Библиотека контента (upload, метаданные, статусы).
- Доставка контента на Android TV (плейлист + кэш + оффлайн-воспроизведение).
- Fleet management (enroll, assignment, heartbeat, версия приложения).
- Overlay/data layer поверх видео:
  - транспорт: **SSE**,
  - модель: `state + patch`,
  - виджеты: текст, бегущая строка, таблица (N строк), KPI плитки, QR/изображение.
- Audit log + базовый as-run.

### 3.2 Explicitly NOT v1 (не делаем)

- Поддержка Tizen/webOS/Windows/WebKiosk.
- Встроенный “графический редактор” уровня AE.
- Персонализация “уникальный видеопоток на каждого пользователя”.
- Рекламная платформа (FAST/SSAI).
- Сложные кампании, A/B, приоритетные окна (после подтверждения спроса).

## 4) Нефункциональные требования (SLO / качество)

- Воспроизведение на экранах: **≥ 99.9% uptime** по плейлисту/месяц (за счёт кэша и fallback).
- “Time-to-publish”: P50 ≤ 2 мин, P95 ≤ 10 мин (реалистично для корпоративных сетей).
- Overlay latency: P95 ≤ 2 сек “данные → экран” при нормальной сети.
- API: P95 ≤ 300ms (внутреннее), ≤ 800ms (через интернет).
- Любая ошибка сети/контента не “гасит экран”: всегда есть fallback (служебный экран + локальный кэш).

## 5) Ограничения (Kotlin-only + минимум систем)

### 5.1 Backend (full-stack Kotlin, монолит)

Монолит — один deployable-артефакт (Docker image / JAR), который включает:

- Control Plane API (admin/integrator)
- Player API (конфиг, плейлист, heartbeat)
- Overlay SSE (стрим + коннекторы источников)
- Ingest (приём файлов + валидация + опциональная нормализация)
- Background jobs (планировщик, коннекторы, ротации/архивация, отчёты)

### 5.2 Минимальный набор внешних систем (pilot)

- PostgreSQL (единственная обязательная внешняя система).
- Storage: локальная файловая система **или** S3-compatible (опционально для production).
- CDN: опционально (появляется при росте числа экранов/географии).

Запрещаем себе по умолчанию: Kafka/Rabbit, Redis, отдельные воркеры, отдельные сервисы авторизации.

## 6) Ключевые допущения (для быстрого MVP)

- Контент v1: MP4 (H.264/AAC) и изображения (PNG/JPEG). Для пилота допускается “без перекодирования”: только проверка и отказ при несовместимости.
- Админ-интерфейс v1 — функционален, но не “дизайнерский”.
- Сценарии данных (очереди/KPI/меню): в пилоте допускается “manual mode” и простые REST pull источники.
- Безопасность: минимальный набор (RBAC + device auth). SSO/OIDC — в R1, если клиент требует.

## 7) Роли и права (RBAC v1)

- `TenantAdmin`: всё в рамках тенанта.
- `Operator`: управление контентом/каналами/расписанием, без управления пользователями/интеграциями.
- `Viewer`: read-only.
- `Integrator`: управление источниками данных и доступ к интеграционным ключам.

## 8) Определения (общий словарь)

- **Tenant** — организация/клиент.
- **Channel** — сущность “что показываем” (плейлист + расписание + overlay binding).
- **Schedule** — версия правил показа по времени.
- **Device** — Android TV устройство/плеер, привязанное к тенанту.
- **Asset** — медиафайл (видео/изображение), используемый в расписании.
- **Overlay profile** — набор виджетов/раскладок.
- **As-run** — фактический лог воспроизведения “что реально показывалось”.
