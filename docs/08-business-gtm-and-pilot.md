# 08 — Бизнес-план: упаковка, GTM и план пилота

## 1) Для кого (ICP) — кто купит быстрее всего

### ICP-1: корпоративные офисы и распределённые филиалы

- 50–200 экранов на старте, рост до 1k+
- сценарии: HR коммуникации, новости компании, KPI, безопасность, объявления

### ICP-2: сервисные точки с очередями (банки, клиники, госуслуги)

- ценность: overlay очереди/табло + управляемый контент

### ICP-3: retail сети (ограниченно)

- ценность: скорость обновления + централизованность
- риск: ожидания “как рекламная платформа” → важно ограничить обещания v1

## 2) УТП (что продаём одним предложением)

“Централизованное управление Android TV экранами + realtime-оверлеи поверх видео, с аудитом и эксплуатацией уровня enterprise, запускаем пилот за 2–4 недели.”

## 3) Упаковка MVP (что обещаем в пилоте)

- Каналы/расписание + быстрая публикация
- Android TV player (кэш, оффлайн, устойчивость)
- Overlay (очереди/KPI/объявления) через SSE
- Fleet: enroll, назначение, статусы устройств
- Audit + базовый as-run

Правило (чтобы пилоты не сжигали команду): пилот по умолчанию **платный**, с KPI (go/no-go) и зачётом части стоимости в первый годовой контракт.

## 4) Модель монетизации (простая и масштабируемая)

Рекомендуем начинать с “per screen / month”:

- Tier S (до 200 экранов) — фикс + лимиты трафика/хранилища
- Tier M (до 1k) — ниже цена за экран, добавляется SSO
- Tier L (enterprise) — индивидуально + комплаенс/интеграции

Опции/аддоны:
- расширенный ретеншн as-run/audit
- custom connectors (ERP/CRM)
- on-prem / isolated environment

## 5) План пилота (пошагово, 2–4 недели)

### 5.1 Подготовка (1–3 дня)

- выбрать 3 локации (например: HQ + 2 филиала)
- утвердить список поддерживаемых Android TV устройств
- подготовить сеть: DNS/443, прокси правила (если есть)
- определить ответственных: бизнес-оператор контента + ИТ владелец

### 5.2 Установка (1–3 дня)

- поднять backend (pilot деплой)
- установить Android TV app на устройства
- enroll + назначить канал/группу

### 5.3 Контент и сценарии (3–7 дней)

- загрузить базовый набор медиа
- настроить 2–3 канала (HQ, филиалы, “служебный”)
- включить overlay:
  - manual mode (быстро)
  - один REST pull источник (если есть)

### 5.4 Измерение успеха (параллельно)

Собрать метрики:
- time-to-publish (p50/p95)
- доля online устройств
- частота ошибок воспроизведения
- latency overlay
- операционные затраты (сколько времени уходит на поддержку)

### 5.5 Итог пилота (1–2 дня)

- отчёт “что получилось / что мешало”
- решение “идём в production hardening (R1) или останавливаем”

## 6) Что может сорвать пилот (и как не сорвать)

- Неподдерживаемые кодеки/битые видео → жёсткая валидация + “эталонный набор” шаблонов контента.
- Нестабильные прошивки Android TV → whitelist моделей + тестовый стенд.
- Сложные интеграции → сначала manual mode, потом 1 интеграция.
